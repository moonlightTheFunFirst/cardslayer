# CardSlayer — Godotプロトタイプ

Windows向け2Dカード戦闘＋装備収集ゲーム。開発仕様は `spec.md`、原案は `readme.txt`。既存の両ファイルは変更していません。

## 環境と起動

- 固定エンジン: **Godot 4.7.2.stable.official.ed1daf0bf**。
- 型付きGDScript、Compatibility / OpenGL、1280×720、リサイズ時はcanvas_itemsでスケール。
- 日本語フォント: WindowsのYu Gothic / MeiryoをSystemFontで利用。フォントファイルの無断コピーは行っていません。日本語フォントのないWindows環境への配布は別途フォント同梱が必要です。
- ランタイムの追加パッケージ・APIキー・ネット接続は不要。

Godotで本フォルダーの `project.godot` をインポートしてF6ではなく **F5** で開始します。

PowerShellでこのフォルダーを開いて実行:

```powershell
.\tools\run.ps1
```

既定のGodot実行ファイル:

```text
F:\tools\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe
```

別の配置では次のいずれかを使用します。

```powershell
$env:GODOT_EXE = 'C:\tools\Godot\Godot_console.exe'
.\tools\run.ps1
.\tools\run.ps1 -Godot 'C:\tools\Godot\Godot_console.exe'
```

## ゲームの操作

1. タイトルの「ゲーム開始」で新しい英雄を作成。「続きから」で既存セーブを読み込みます。
2. 本拠地のメニュー「出撃」から朽ち森へ。開始→AまたはB→C→ボスの順に接続先を選択します。
3. 戦闘はSlay the Spire風の画面です。手札のカードにマウスを乗せると拡大表示。単体攻撃は敵へドラッグ（またはクリックで選択→敵をクリック）すると矢印と照準が出て使用します。自己・全体対象のカードは手札より上へドラッグ（またはクリック→画面上部をクリック）で使用します。
4. 右クリックまたはEscで選択を解除。数字キー1〜0でカード選択、Eキーか「ターン終了」で敵が順に行動します。敵の頭上は次の行動の予告（剣=攻撃、盾=ブロックなど）で、キャラクターにマウスを乗せると詳細を表示します。
5. 勝利した時点で報酬を一度だけ確定。「次へ」で探索を続行し、ボス撃破後は本拠地へ戻ります。
6. 本拠地の「装備」で入手品を装備し、「デッキ編集」でカードを増減できます。20枚から交換する場合は先に1枚追加してから不要な1枚を減らしてください。

手札は保持されます。初回5枚、以降は毎ターン1枚を引き、使用したカードは山札の底へ戻ります。手札は扇状に並び、10枚でも全カードにマウスを乗せて確認できます。カード表示のダメージ値は現在の能力を反映し、対象のブロック適用前の値です。毒による次回行動前の死亡など、将来の変化は敵の予告値に織り込みません。

戦闘の「撤退」とマップの「本拠地へ帰還」は確認ダイアログ付きです。撤退・敗北・クリアで本拠地へ帰還し全回復。確定済みの報酬は保持します。

戦闘画面上部のバーに「◀ エディタ (F1)」「ログ」「BGM/SE: ON/OFF」「撤退」があります。**F1キーでどの画面からでもエディタへ戻れます**（テストプレイ中は編集していた項目へ戻り、通常プレイ中はセッションを保持したまま開きます）。

## 本拠地とショップ（spec.md 21章）

本拠地はドット絵の背景とメニューの画面です。メニューから次の画面へ移動し、各画面の「◀ 本拠地へ戻る」で戻ります。

| メニュー | 内容 |
| --- | --- |
| 出撃 | エリアのマップへ。マップの「本拠地へ帰還」でいつでも戻れます（出撃進行は破棄） |
| デッキ編集 | カード絵つきの一覧で −／＋。20～30枚、同じカードは10枚まで。押せない理由はボタンのツールチップに表示 |
| 装備 | 7つの装備枠と所持品。装備後の能力と装備条件を表示 |
| 持ち物 | 所持している消費アイテムと、出撃に持っていく「持ち込み」の設定 |
| カード一覧 | 全カードを現在の能力で計算した数値つきで表示 |
| 主人公の状態 | レベル・EXP・所持金、基礎能力と装備込みの能力、装備中の品、初クリア済みエリア |
| ショップ | ランダムな装備品を購入（今は購入のみ）。「◀ 本拠地へ帰還」で戻ります |
| 背景 | 森の野営地／石造りのアジト／夕暮れの見張り塔を順に切り替え。セーブに保存 |

ショップの品揃え（装備品と消費アイテム）は新規開始時と、出撃から本拠地へ戻るたび（クリア・敗北・撤退）に入れ替わり、セーブに保存されます（ロードし直しても変わりません）。装備品・消費アイテムの品数、装備の等級の出現重み、装備の価格（基本価格＋レベル加算）×等級倍率は、総合エディタの「ルール」タブ `shop` で編集できます。消費アイテムの価格と出やすさは各アイテムの定義で設定します。

## 消費アイテム（spec.md 20章）

デッキとは別に、所持している消費アイテムから出撃に持っていく分を「持ち込み」に入れます。持ち込める数は `rules` の `items`（`carry_limit`、初期値3）で変更できます。新しい英雄は薬草2個を持ち込んだ状態で始まります（`starter`）。

- **戦闘**: 上部バーのアイテム枠をクリックして使用。敵が対象のアイテムは、クリックしてから敵をクリックします（右クリック／Escで取消）。使用条件を満たさないアイテムはグレー表示になり、理由をツールチップに表示します。
- **マップ**: 「戦闘・マップ」で使えるアイテム（薬草など）は「○○を使う」ボタンで使えます。
- 使ったアイテムは所持数と持ち込みの両方から減ります。

サンプル: 薬草（HP7～20回復、HP満タンでは使用不可）、万能薬（バッドステータスを1つ解除、複数ならランダム）、パワー丸（戦闘中 力+3）、ディフェンス丸（戦闘中 被ダメージ-3）、雷の小瓶（選んだ敵に12～18ダメージ）、運命のサイコロ（スクリプト製。出目で効果が変わる）。パワー丸・ディフェンス丸の値は仮の値で、エディタで調整できます。バッドステータスは現在、毒だけです。

### エディタでの編集

総合エディタの「消費アイテム」タブで、名前・説明・価格・ショップ出現重み・アイコン・使用時SE・使用時エフェクト（きらめき／破裂／発光／なし）・エフェクト色・使用場面（戦闘中のみ／戦闘・マップ）・対象（自分／選択した敵）・使用条件・基本効果を選んで編集します。

特殊なアイテムは「効果スクリプト」にGDScriptを書きます。空欄なら、選んだ使用条件と基本効果がそのまま使われます。

```gdscript
func can_use(ctx):          # 省略可。"" なら使用可、文字列ならグレー表示の理由
	return ctx.basic_reason()   # 選んだ使用条件の判定

func use(ctx):              # 必須
	ctx.apply_basic()           # 選んだ基本効果を実行
	if ctx.rand_int(1, 6) == 6:
		ctx.damage_all(10)
```

`ctx` で使える機能: `in_battle()` `hp()` `max_hp()` `mp()` `max_mp()` `stat(名前)` `bad_statuses()` `has_target()` `target_hp()` `rand_int(a, b)`、`heal(n)` `restore_mp(n)` `add_block(n)` `add_stat("strength", n)` `reduce_damage(n)` `cure("poison")` `cure_random()` `damage_target(n)` `damage_all(n)` `draw(n)` `message(文字)`。

- 「検証」ボタンで構文と設定を確認でき、保存時にも同じ検証をします。
- スクリプトでは、ファイル・OS・エンジンに触れる語（`OS`、`FileAccess`、`load` など）を拒否します。ただし完全なサンドボックスではないため、信頼できるデータだけを使ってください。
- 実行時のエラーは検出できません（Godotの出力に表示されます）。
- 「試用シミュレーション」で、テスト設定の英雄（HP半分・毒3）と敵を使って、戦闘中とマップでの使用結果を表示します。
- 「テスト設定」の「消費アイテム」に入れたものは、戦闘テスト／エリア試遊で持ち込まれます。

アイテムの乱数は戦闘のシードから作った別系統を使うため、同じシードなら同じ結果になり、山札の順番にも影響しません。

### デバッグメニュー

開発機能が有効なとき、本拠地の上部バー「デバッグメニュー」から、同じ機能をフォーム形式で操作できる画面へ移動します（主人公の状態・カード一覧・デッキ編集・装備・ショップ・背景・出撃）。各ページの「実画面で表示」で対応する実画面に戻ります。

デバッグメニューと実画面は、どちらも `HubActions`（デッキ・装備・背景）と `Shop`（品揃え・購入）の同じ処理を呼びます。機能を変更するときは両方の画面を合わせて修正してください。`tests/hub.gd` は両画面から同じ購入をして結果が一致することを確認しています。

## エディタ→テスト→復帰

タイトルの「総合エディタ」、本拠地・戦闘画面の「◀ エディタ (F1)」、マップの「開発メニュー」から開きます。

- カード・敵・装備・アフィックス・エリア・計算式・ルール・テスト設定をフォームで編集できます。
- 左側で検索・選択し、右側で数値や選択肢を変更。効果・敵行動・ノード等の配列は追加・削除・上下移動できます。
- 保存済みの定義IDは直接変更できません。「複製」で新IDを指定します。「新規」は選択項目を雛形にします。
- 参照中の定義削除は拒否し、参照元や必要な制約を表示します。
- タブ・項目を移動してもドラフトは保持されます。再読込・編集終了・ウィンドウ終了時に未保存なら保存／破棄／キャンセルを表示します。
- 計算式タブのサンプル入力と「評価」で試算できます。許可変数はbase、scaling、strength、wisdom、agility、luck、max_hp、max_mp。四則演算・括弧・単項マイナスのみ、最大512文字です。
- テスト設定で基礎能力・現在HP・カード構成・装備基底ID・敵構成・エリア・シードを指定します。装備はシードから生成するLv.1のコモン個体、同じ部位は1個、レベル1の装備条件を満たす必要があります。両手武器と右手・左手は併用できません。
- 敵タブの「この敵をテスト対象に設定」、エリアタブの「このエリアを試遊対象に設定」を使えます。
- 「保存して戦闘テスト」「保存してエリア試遊」は定義検証に成功した場合だけ保存し、再読込して開始します。テスト設定自体も開始前に検証します。
- テスト中は常に表示される「編集へ戻る」で、編集タブ・ID・スクロール位置へ復帰。「同じ条件で再試行」「新しいシードで再試行」も利用できます。

通常プレイ中に編集を開いた場合は、そのセッションと乱数状態を保持します。テスト経験値・装備・ゴールドは通常セーブへ書き込みません。編集終了で通常プレイへ復帰します。変更した定義は進行中の通常セッションには反映せず、次の出撃時に反映します。参照IDを削除して通常セーブが読み込めなくなった場合は、その定義を復元してください。

## 保存先とデータ

通常セーブは現在 `save_version=4` です。version 3 で本拠地の背景 `hub_background` とショップの品揃え `shop.stock`、version 4 で所持消費アイテム `consumables` と持ち込み `loadout` を追加しました。version 3 は消費アイテムなし、version 2 はさらに背景を森の野営地、品揃えを空として移行し、読込直後に品揃えを生成します。旧版（version 1）は読込時にメモリー内で移行し、旧装備のinstance_idとアフィックスの個数・値を保持します。旧コモンの0個付与も再抽選しません。移行だけでは元ファイルを書き換えず、その後の通常の保存時にversion 4として保存します。新しく生成した装備はレベルと基礎補正も個体に記録し、ロードで再計算・再抽選しません。

各JSONはUTF-8、schema_version=1です。`data/`にcards、enemies、items、affixes、areas、formulas、rules、consumablesを分離しています。以前に作られた編集用データ（エクスポート版の `user://editor_workspace/data/` など）に consumables.json がない場合は、読み込み時に同梱の consumables.json を自動でコピーします。`rules` の `shop`／`items` がない場合は既定値で動作します。

| 用途 | 保存先 |
| --- | --- |
| Godotから開発実行する定義 | `res://data/`（本プロジェクトのdataフォルダー） |
| エクスポート開発版の定義 | `user://editor_workspace/data/`（初回に同梱データ一式をコピー） |
| 通常セーブ | `user://saves/profile.json` |
| Windowsでのuser:// | `%APPDATA%\Godot\app_userdata\CardSlayer\` |
| 自動検証用セーブ・画像 | プロジェクトの `.godot/tests/` |
| エクスポート版スモーク検証 | `user://smoke/` |

定義の保存は全ファイルを一時書き込みし、バックアップ後に置き換えます。置換失敗時はバックアップから復元します。各ファイルの書き込み失敗は表示します。複数ファイルの更新中にプロセスやOSを強制終了した場合の完全なトランザクション保証はありません。必要に応じて同じ保存時点の `.bak` 一式から復元してください。

セーブは本拠地のデッキ・装備・背景の変更、ショップでの購入、勝利報酬確定、帰還時に保存します。**戦闘途中・マップ位置は再開しません。ロード後は全回復した拠点からです。** 不正JSON・欠落ID・非対応バージョンは理由を表示し元ファイルを保持します。壊れたセーブを検出した実行中は上書きを禁止します。復旧にはアプリを終了して元ファイルを退避し、バックアップや定義を修復してください。

エクスポート開発版で編集した内容をプロジェクトへ戻すには「書き出し」で空のディレクトリを選び、出力された8つのJSONを、アプリを終了したうえでプロジェクトのdataへまとめてコピーします。コピー前のdataは退避し、コピー後に自動検証を実行してください。ゲームとエディタで異なるデータルートを混ぜません。

## Windowsエクスポート

`export_presets.cfg` の **Windows Development** を使用します。

1. Godot 4.7.2のエクスポートテンプレートをGodotのテンプレートマネージャーでインストールします。
2. `.\tools\export.ps1` で `build/CardSlayer.exe` と `build/CardSlayer.pck` を生成します。
3. **exeとpckを同じフォルダーに置いて**実行します。

この作業環境では公式4.7.2テンプレートのWindows x64版を `.godot/templates/` に配置済みです。export.ps1はこれが存在する場合に限り一時的なカスタムテンプレート設定を使用し、終了時にプリセットを復元します。別環境では標準のテンプレートマネージャーを使用できます。

リリーステンプレートで出力する場合は `-Release` を指定します。開発機能を無効にする場合はproject.godotの `cardslayer/development_enabled=false` にして再エクスポートします。今回の出力は開発用で、署名・Steam連携・正式配布パッケージは含みません。正式配布前にフォント同梱方針とGodot・依存ライブラリのライセンス表記を整備してください。

## 検証

```powershell
.\tools\test.ps1
.\tools\run.ps1 -Headless
& $env:GODOT_EXE --path . --script res://tests/visual.gd
```

test.ps1はGodotヘッドレスでロジックと実シーンの遷移、マウス入力イベントによる装備生成・戦闘・本拠地（`tests/hub.gd`）・消費アイテム（`tests/items.gd`）の操作を検証し、失敗時に終了コード1を返します。初めてのチェックアウトでは先にGodotへインポートしてください。

visual.gdは実際のWindows/OpenGLウィンドウを短時間表示し、画面を順に構築して `.godot/tests/` にスクリーンショットを保存します。実装の呼び出しによる自動操作であり、人による通しプレイの代用と断定するものではありません。

エクスポート版の保存・ロード検証:

```powershell
$p = Start-Process -FilePath '.\build\CardSlayer.exe' -ArgumentList '--headless','--','--smoke' -WindowStyle Hidden -PassThru -Wait
$p.ExitCode
Get-Content "$env:APPDATA\Godot\app_userdata\CardSlayer\smoke\report.json"
```

これは開発機能有効時だけ動作し、専用セーブを使用します。専用の定義コピーで斬撃威力と抽選設定を一時変更して元の値に戻します。

現在のスモーク検証は定義も `user://smoke/data_v2/` の専用コピーを使用します。普段の編集ワークスペースは変更せず、生成設定の保存・再読込・復元も検証します。

実施結果は `VERIFICATION.md` に記録しています。

## 構成・仮仕様・制限

- DefinitionRepository: ルート選択、JSON型・範囲・参照・グラフ検証、保存。DefinitionModelsで検証済み定義を型付きレコードへ変換。
- BattleEngine: UIから独立したRefCounted。FormulaEvaluatorと共通効果解決を使い、カードIDによる効果の分岐はありません。行動結果は即時に確定し、演出用に `events`（カード使用・効果・毒・ドロー・ターン）を記録します。
- BattleView / BattleCard / BattleActor: 戦闘画面。`events` を順に再生してアニメーションとSEを付け、終了後にmain.gdの `after_action` へ渡します。自動検証から呼ぶ `use_card` は従来どおり演出なしで即時に進みます。
- Sound: BGM（拠点・通常戦・ボス戦）のループ再生とSEのボイスプール。
- HubView: 本拠地・状態・カード一覧・デッキ編集・装備・持ち物・ショップの実画面。HubActions / Shop が両画面共通の処理、PixelUi が戦闘画面と共通のボタン・パネル。
- ItemRunner / ItemContext: 消費アイテムの検証・スクリプトのコンパイル（キャッシュ）・実行と、スクリプトから使えるAPI。戦闘中はBattleEngine経由で効果を適用して演出に記録し、マップではHP/MPを直接変更します。
- Progression: 基礎能力・装備補正、経験値、抽選と報酬確定。SaveRepository: 通常セーブの検証と保存。
- main.gd: ゲーム／編集／テストの遷移、停止中セッションと乱数の保持。DefinitionEditor: 共通リポジトリを使うフォーム。
- CardView: 本番・エディタで共通のカード部品。プレースホルダーは色分けしたカードです。
- 敵の行動値は予告時点の状態を使います。式の実行エラーでは戦闘を停止し、原因を表示します。整数化前の正値が2,147,483,647を超える式結果も拒否します。
- ルールはspec.mdの仮仕様を維持。AP3、初回5枚、次ターン1枚、上限10枚、MP2回復。全カード解放済み、初期20枚、各種類最大10枚です。
- サンプル敵は通常3種＋ボス1種。初回でも攻略可能なHP・行動値を設定しました。自動操作20シードの勝利は難易度評価の代わりではありません。
- 装備9基底、9アフィックス。基底候補は均等抽選（候補リストで設定）、等級は初期値70/25/5/0/0。敏捷・運は装備条件と表示のみ。
- 初クリア100G、必要経験値は現在Lv×30。レベルアップで現在HPは回復せず、戦闘中強化は次の戦闘へ持ち越しません。

## ランダム装備品ジェネレーター（spec.md 17〜19章）

タイトルの「装備品ジェネレーター」、または総合エディタの「装備ジェネレーター」タブから利用します。**通常戦利品にも同じ新ルールを適用**しています。

1. 「生成条件」で装備レベル（1〜999）・生成数（1〜200）・シード・等級・部位・基底IDを指定します。空の選択は全候補／等級重み抽選です。
2. 「装備を生成」で未保存のドラフトも含めて検証し、成功すると「生成結果」へ切り替えて生成件数と一覧を先頭から表示します。生成できない条件では理由をダイアログで表示します。生成品は保存されず、通常の所持品にも追加されません。
3. 同じ条件・シード・定義なら同じ結果。「新シードで生成」で再抽選します。
4. 「等級・確率・値範囲」で等級の抽選重み、各等級のアフィックス数の重み、アフィックスごとの候補重み・通常値範囲・特別ロール確率と値範囲を編集します。
5. 上部の「保存」で設定を保存。通常プレイには次の出撃から反映します。

装備名は「ランダムな名前＋左右を繋ぐ形容句＋ランダムな名前」で生成します（例: 月影を纏う銀冠）。末尾の語句は装備部位に応じた候補から選び、基底名は別途表示します。通常戦利品にも適用し、入手時の名前をセーブに保持します。既存の名前未設定品は従来の基底名で表示します。命名には独立した乱数器を使うため、能力値の抽選列は変わりません。

設定は既存の7ファイル構成を維持し、`rules.json` の `loot` レコードに保存します。等級そのものの抽選重みは `combat.rarity_weights`、基底候補は `combat.loot_bases` です。アフィックスの実際の出現重み・値範囲は **等級別設定** を使います。`affixes.json` のmin/maxは新しい候補設定を追加する際の初期値です。

| 等級・文字色 | 個数 | 初期の個数確率 |
| --- | --- | --- |
| コモン・白 | 1 | 100% |
| マジック・青 | 1〜2 | 70% / 30% |
| レア・黄 | 3〜7 | 70% / 24% / 5.9% / 0.09% / 0.01% |
| レジェンダリー・茶 | 1〜2 | 40% / 60% |
| ユニーク・紫 | 1〜2 | 40% / 60% |

重みは合計で正規化し、0は対象外です。アフィックスは基底候補と等級別の有効候補の共通部分から重複なしで抽選します。最大抽選個数に対して候補が足りない、全重み0、負値、不正な範囲、参照切れなどは保存・生成を阻止します。

コモンは各付与アフィックスについて初期1%で「特別ロール」を行い、同じアフィックスのレア通常最大値を超える値を出せます。マジック専用の「蒼星の祝福」は重み1、他の8候補は各100で、レア等の重みは0です。複数個抽選時は選ばれた候補を除いて次を抽選するため、候補重みは固定の最終付与確率ではありません。

既存の70/25/5の等級比率を維持するため、レジェンダリー・ユニークの通常抽選重みの初期値は0です。ジェネレーターで等級を明示すれば生成でき、等級重みを正にして保存すれば通常戦利品にも出現します。これらの固有効果は今回追加していません。

基礎値は装備タブの「基礎補正」「1レベルごとの成長」で調整します。

```text
基礎値 = floor(Lv.1の基礎補正 + 成長値 × (装備レベル - 1))
```

たとえば剣の力は初期2、成長0.4でLv.11なら6です。戦利品のレベルは報酬処理後の英雄レベル（上限999）。装備には基底の装備条件に加えて個体レベル以上の英雄レベルが必要です。アフィックス値のレベル倍率は導入せず、等級別の値範囲で調整します。

装備部位は頭・胴・腕・右手・左手・両手・足です。両手武器を装備すると右手と左手を外し、右手または左手を装備すると両手武器を外します。外した品は所持品に残ります。サンプルの旧ring IDは「剛力の籠手」、charm IDは「灯火の兜」に名称・部位を更新し、安定IDは維持しました。

以前のエクスポート開発版から更新する場合、旧定義に新部位・抽選設定がないため起動時に検証エラーを表示します。「新しい同梱定義を導入」で確認すると、旧編集データ一式を `user://editor_workspace/backup_日時_識別子/` へ退避してから新しい同梱定義一式に置き換えます。**カスタム編集内容がある場合はバックアップと比較して反映し直してください。** 通常セーブはこの操作では変更しません。プロジェクトのres://dataはこのボタンでは置換しません。

## 画像・音声アセット

`assets/` のドット絵とチップチューンは、すべてスクリプトで生成しています（外部素材・フォントの同梱なし）。

| 内容 | 生成スクリプト | 出力 |
| --- | --- | --- |
| 主人公・敵4体・予備スライム・背景（通常／ボス）・カード枠3種・カード絵・アイコン・UIパネル | `tools/gen_assets.py`（補助: `tools/pixel.py`、Pillow + numpy） |
| 本拠地の背景3種・ショップの背景 | `tools/hub_art.py`（gen_assets.pyから呼び出し） |
| 消費アイテムのアイコン8種 | `tools/item_art.py`（gen_assets.pyから呼び出し）→ `assets/items` | `assets/sprites`, `backgrounds`, `cards`, `ui` |
| BGM 3曲（拠点・通常戦・ボス戦、シームレスループ）とSE 25種 | `tools/gen_audio.py`（numpy） | `assets/audio` |

```powershell
python tools/gen_assets.py
python tools/gen_audio.py
```

再生成後はGodotで一度開く（または `--headless --import`）と取り込まれます。画像は1倍で出力し、ゲーム内では最近傍補間の整数倍（キャラクター3倍、カード2倍、ホバー時3倍）で表示します。

カード絵は `image_path` が空なら `assets/cards/art/<カードID>.png`、無ければカテゴリ別の既定絵を使います。敵は `assets/sprites/enemies/<敵ID>.png`、無ければ `default.png`（スライム）です。エディタで追加したカード・敵も画像なしで戦闘に出せます。
